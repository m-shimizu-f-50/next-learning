# Next.js演習コードレビュー（JS経験者向け）

## 前提

レビュー対象は素のJavaScript経験者がReact/Next.js/TypeScriptを学習中に書いた演習コード。「知らない構文」ではなく「素のJSの感覚のままReact/Next.jsを書いてしまっている箇所」を優先的に指摘する。

## チェック観点（優先度順）

1. **TypeScriptの型**: `any`への逃げ、propsやstateの型注釈漏れ、型推論に任せてよい箇所への過剰な明示、JSの緩い型変換の感覚(暗黙のtruthy判定や`==`)が残っていないか。CLAUDE.mdの「型安全を徹底」に沿っているか。型定義がコンポーネント関数の中に書かれていないか(再利用性・可読性のため関数外・トップレベルに出すのが基本)。`res.json()`など`any`を返すAPIに型注釈だけを当てて満足していないか(実データとのズレをコンパイラは検知できない)
2. **null/undefined安全性**: optional chaining(`?.`)・nullish coalescing(`??`)を使うべき箇所で素の条件式やデフォルト値の書き方(`||`)に頼っていないか、`strictNullChecks`を意識した設計になっているか
3. **コンポーネント設計と責務分離**: 1コンポーネントに複数の責務(データ取得・状態管理・表示)が混在していないか。CLAUDE.mdの「コンポーネントは責務を分離」に沿っているか。propsのインターフェース定義は明確か
4. **状態管理と副作用**: `useState`/`useEffect`の使い方。JSのDOM操作・手続き的な感覚(直接DOM書き換え、イベントリスナーの手動着脱)が残っていないか。`useEffect`の依存配列漏れ・不要な再実行がないか
5. **JSX特有の書き方**: 条件レンダリングの書き方(`&&`と三項演算子の使い分け)、リストレンダリング時の`key`の付け方(indexをキーにしていないか)、イベントハンドラの命名・受け渡し方
6. **Next.js特有の概念**: App Routerでのファイルベースルーティング、Server ComponentsとClient Componentsの使い分け(`'use client'`の要否)、データ取得の書き方(Server Componentでの`fetch` vs クライアント側`useEffect`)。JSのSPA的な「全部クライアントで取得」の感覚のままになっていないか
7. **命名規則**: コンポーネント名はPascalCase、hooksは`use`プレフィックス、ファイル名・ディレクトリ構成の規則。CLAUDE.mdの「命名規則を統一」に沿っているか
8. **非同期処理**: `useEffect`内で直接`async`関数を渡していないか(IIFEやヘルパー関数化が必要な点はJSの素のasync/awaitと異なる)、ローディング・エラー状態の扱い漏れ。`fetch`はHTTPエラー(404/500等)でも例外を投げない点を理解した上で、`res.ok`チェック等のエラーハンドリングが書かれているか(Server Componentsでは`throw`することで最寄りの`error.tsx`に処理を委譲できる)
9. **環境変数・秘匿情報の扱い**: `NEXT_PUBLIC_`プレフィックスの意味(付けるとクライアントにも露出する)を理解しているか、Client Componentの中でAPIキー等の秘匿情報を扱っていないか。「環境変数はどこからでも読める」という素のJS/Node.jsの感覚が残っていないか
10. **Next.js特殊ファイル規約の活用**: エラー・ローディング表示を自前の`if`分岐やtry/catchだけで実装せず、`error.tsx`・`loading.tsx`・`notFound()`などApp Router標準の仕組みを使えているか
11. （進捗が進んだら）**再レンダリング最適化**: `useMemo`/`useCallback`/`React.memo`の使い所。JSのforループ最適化の感覚とは異なる、Reactのレンダリングモデルを踏まえた判断ができているか
12. （Chapter5以降で有効化）**データフェッチの重複・キャッシュ**: 同じデータを複数コンポーネントで個別にfetchしていないか、Request Memoizationを理解した上で書けているか

## フィードバックの出し方

CLAUDE.mdの「不明点は質問する」「勝手に仕様を変更しない」という方針、および学習目的である点を踏まえ、以下の順で返す。

1. 良い点を先に1〜2個挙げる
2. 素のJSの感覚のまま書いている箇所を指摘し、「JSではこう書くが、Reactではこう考える」「JSではこう書くが、Next.jsではこう考える」という対比で説明する
3. 改善コード例を示す
4. 理解度を確認する質問を1つ添えて終える（次の演習にそのまま進めるかの判断材料にする）
